# Contributing

Help researchers find useful world-model papers, implementations and benchmarks. New papers, resource updates and corrections are all welcome.

## Suggest a paper or correction

[Open an issue](https://github.com/House-yuyu/Awesome-World-Models/issues/new) with:

- The paper title and an official paper or publication link.
- The most relevant category and a sentence explaining what the model predicts, simulates or controls.
- Official code, project or data links, with their current availability.
- Publication status: published, accepted or preprint. Include an official source for an acceptance claim.

For a correction, identify the existing entry and the source supporting the change. Related representation models and simulators should be described precisely; inclusion does not imply that they are validated causal world models.

## Submit a pull request

The source of truth is [`data/papers.yaml`](data/papers.yaml). The README's paper tables, collection navigation and metadata badges are generated by [`scripts/generate_readme.py`](scripts/generate_readme.py).

1. Add or update the record in `data/papers.yaml`. Keep `model` as the first field for readability, and update `updated_date` when the catalog changes.
2. Add a short entry to the README's **Recent Updates** when appropriate.
3. Regenerate and check the README, then include both the YAML and README changes in your pull request:

```bash
pip install -r requirements.txt
python scripts/generate_readme.py
python scripts/generate_readme.py --check
```

Do not edit inside `PAPERS_START` / `PAPERS_END` or `NAVIGATION_START` / `NAVIGATION_END` directly: those blocks are overwritten during generation. The cover, introduction and reading routes can be edited normally.

## Metadata

Required fields: `model`, `title`, `paper_url`, `year`, `venue`, `category` and `focus`.

Use `publication_status: preprint` for an arXiv preprint, `accepted` for a verified acceptance, or `published` for a published paper. Record `arxiv_id`, `published_date`, `added_date`, `verified_date` and supporting `sources` when available. The first-posted date and the publication year may differ.

| Code status | Meaning |
| --- | --- |
| `released` | An official implementation is available. |
| `partial` | Only part of the implementation is available. |
| `unreleased` | A repository exists, but implementation code is pending. |
| `unverified` | No accessible official implementation has been confirmed; this does not establish that code has never been released. |
| `repository-only` | An official repository is available; do not label it as implementation code. |
| `data-only` | The resource provides data rather than model code. |

Keep `code_url` empty when no official resource has been verified. Use `project_url` for a project page and `resources` for additional labeled links, such as weights or datasets.

## Categories

| Collection | Category values |
| --- | --- |
| Surveys / foundations | `survey`, `foundations` |
| Interactive / embodied | `interactive`, `robotics` |
| Medicine / society / science | `medical`, `social`, `physics` |
| Earth observation | `eo-forecast`, `eo-spatial`, `eo-representation` |
| Video / general evaluation | `video-spatial`, `bench-general` |
| Driving models | `generative`, `latent`, `world-action`, `jepa`, `vla-world` |
| Driving context / evaluation | `vla-general`, `benchmark` |

Every paper has one primary category. The generator rejects unknown categories and duplicate model names, titles, paper links or arXiv identifiers. Use the parsed `papers` list length reported by `--check` for counts; counting `- model:` lines is unreliable because YAML field order can vary.
